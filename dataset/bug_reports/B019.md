## Issue Report

> I can't log in even though I'm using the correct password. I registered successfully
> but every login attempt fails with an authentication error.

## Expected Behavior

`login_user` raises HTTP 401 only when the password does **not** match the stored hash.
Providing the correct password returns the user object (HTTP 200).

## Actual Behavior

The verification condition is inverted: HTTP 401 is raised when `pwd_context.verify()`
returns `True` (correct password). Login succeeds only when the password is wrong.

## Root Cause Description

`auth_service.py` line 23:
```python
# BUG
if pwd_context.verify(password, user.hashed_password):
    raise HTTPException(status_code=401, detail="Incorrect password.")
# CORRECT
if not pwd_context.verify(password, user.hashed_password):
    raise HTTPException(status_code=401, detail="Incorrect password.")
```
The missing `not` inverts the logic. In practice, combined with B020 (plaintext password
storage), `verify()` always raises an exception, so all logins return HTTP 500.

## Reproduction Steps

1. Register with password `correctpass`.
2. Log in with password `wrongpass` — this would succeed if hashing worked correctly.
3. Log in with password `correctpass` — observe HTTP 401.
