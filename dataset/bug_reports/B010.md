## Issue Report

> The checkout endpoint returns HTTP 400 when the cart has items but succeeds silently
> when the cart is empty. The empty-cart guard appears to be backwards.

## Expected Behavior

`POST /checkout/` returns HTTP 400 with "Cannot checkout with an empty cart" when no
items exist. It proceeds and creates an order when items are present.

## Actual Behavior

The guard `if items:` raises 400 when the cart is **non-empty** (truthy). An empty cart
passes through the guard without error.

## Root Cause Description

`checkout_service.py` line 13:
```python
# BUG
if items:
    raise HTTPException(status_code=400, detail="Cannot checkout with an empty cart.")
# CORRECT
if not items:
    raise HTTPException(status_code=400, detail="Cannot checkout with an empty cart.")
```
The `not` negation is missing. Every checkout attempt with items in the cart is rejected.

## Reproduction Steps

1. Add a product to a user's cart.
2. `POST /checkout/?user_id=N`.
3. Observe HTTP 400 — checkout is rejected despite having cart items.
