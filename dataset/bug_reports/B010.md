# Bug Report: B010

- **Category**: logic
- **Difficulty**: medium
- **Issue Report Quality**: moderate
- **Scope**: single-file

## Issue Report

I get an error when trying to check out a cart with items, but an empty cart doesn't give any error.

## Expected Behavior

Checkout should reject empty carts (HTTP 400) and proceed with non-empty carts.

## Actual Behavior

Checkout rejects non-empty carts and allows empty carts to proceed.

## Root Cause

- **File**: app/services/checkout_service.py
- **Function**: checkout
- **Lines**: 12
- **Affected Files**: app/services/checkout_service.py

### Description

The empty-cart guard condition is inverted: it checks 'if items:' (truthy = non-empty) and raises 400, instead of 'if not items:'.

## Reproduction Steps

  1. Create a product and add it to cart.
  2. Attempt checkout.
  3. Observe that a 400 error is raised despite the cart having items.
