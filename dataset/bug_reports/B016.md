## Issue Report

> `POST /auth/register` allows two accounts to be created with the same email address.
> The second registration should return HTTP 400.

## Expected Behavior

Registering with an email that already exists returns HTTP 400 with an error message
indicating the email is already in use.

## Actual Behavior

`register_user` queries for an existing user but never acts on the result. The duplicate
insert proceeds, either creating a second user record or raising a database integrity
error (HTTP 500) rather than a clean HTTP 400.

## Root Cause Description

`auth_service.py` lines 10–11:
```python
existing = db.query(User).filter(User.email == email).first()
hashed = password  # proceeds unconditionally
```
The result `existing` is fetched but the check `if existing: raise HTTPException(400)`
is absent. The duplicate-email guard is silently ignored.

## Reproduction Steps

1. `POST /auth/register` with `email=test@example.com`.
2. `POST /auth/register` again with `email=test@example.com`.
3. Observe the second call does not return HTTP 400.
