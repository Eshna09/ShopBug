## Issue Report

> Something is wrong with the cart totals on checkout. The amount charged doesn't make
> sense — it's much lower than what the products cost.

## Expected Behavior

`get_cart_subtotal` returns `sum(item.product.price × item.quantity)` for all cart items.

## Actual Behavior

`get_cart_subtotal` returns `sum(item.product.stock × item.quantity)` — using the stock
count as if it were the price. A $100 product with stock=5 purchased in quantity=2 yields
a subtotal of $10 instead of $200.

## Root Cause Description

`cart_service.py` line 59:
```python
# BUG
return sum(item.product.stock * item.quantity for item in items)
# CORRECT
return sum(item.product.price * item.quantity for item in items)
```
`product.stock` (an integer inventory count) is multiplied by `quantity` instead of
`product.price` (a float monetary value). The subtotal is used by `checkout_service`
to compute the order total, so the final charge is also wrong.

## Reproduction Steps

1. Create a product with `price=100.00`, `stock=5`.
2. Add 2 units to a user's cart.
3. Call checkout or retrieve the subtotal.
4. Observe subtotal = 10.0 (5×2) instead of 200.0 (100×2).
