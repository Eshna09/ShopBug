## Issue Report

> I just registered an account and immediately tried to log in with the same password
> but it said my credentials were incorrect.

## Expected Behavior

Passwords are hashed with bcrypt at registration so that `pwd_context.verify()` succeeds
on subsequent login with the same password.

## Actual Behavior

The password is stored as plaintext (`hashed = password`). `bcrypt.verify(plaintext,
plaintext)` fails because a raw string is not a valid bcrypt hash, causing login to raise
an exception.

## Root Cause Description

`auth_service.py` line 11:
```python
# BUG
hashed = password
# CORRECT
hashed = pwd_context.hash(password)
```
`pwd_context` is imported at the top of the file but is never used in `register_user`.
The plaintext password string is stored directly in the `hashed_password` column,
so `pwd_context.verify()` always fails because it cannot interpret a plaintext string
as a bcrypt hash.

## Reproduction Steps

1. `POST /auth/register` with `password=mypassword`.
2. Query the database — observe `hashed_password = "mypassword"` (plaintext).
3. `POST /auth/login` with the same password — observe login failure.
