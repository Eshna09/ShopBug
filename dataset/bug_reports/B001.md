## Issue Report

> After logging in, my cart shows nothing and I can't add anything to it.
> Everything works fine if I register fresh, but logging into an existing account
> breaks the whole site.

## Expected Behavior

After a successful login the user's ID is stored correctly in application state so that
cart retrieval, Add to Cart, and checkout operations all work without error.

## Actual Behavior

After login, `user.id` is stored as `undefined`. Every subsequent API call that uses
`user.id` — cart fetch, add to cart, checkout — sends `undefined` as a path segment or
query parameter, causing the requests to fail.

## Root Cause Description

`AuthContext.jsx` `login()` reads `data.id` from the API response. The `POST /auth/login`
endpoint returns `{ user_id, email, message }` — there is no `id` field. The correct
field is `data.user_id`. Because `data.id` is `undefined`, `user.id` is stored as
`undefined` and all cart-related API calls break silently.

## Reproduction Steps

1. Register a new account — confirm it works and the cart loads.
2. Log out of the account.
3. Log in with the same credentials.
4. Navigate to the Cart page — observe the cart fails to load.
5. Navigate to Products and click Add to Cart — observe an error.
